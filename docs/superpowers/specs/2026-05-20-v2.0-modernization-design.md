# MachinaWards v2.0 — Design Spec

**Date:** 2026-05-20  
**Status:** Approved  
**Target:** Purpur 1.21.11 (Paper-based), Java 21, custom bash build (`run.sh`)  
**Version bump:** `1.9.1` → `2.0.0`

---

## 1. Goals

1. Fill every remaining griefing vector in `ProtectionListener` with event handlers that fire before block calculation
2. Modernize all deprecated Paper/Spigot API calls to Adventure API (Components, Titles, Action Bars, Chat Events)
3. Fix structural bugs (static pending maps, un-cached config reads, MySQL single-connection fragility)
4. Add VISITOR/MEMBER trust levels with a beginner-friendly inventory GUI
5. Remain 100% backward compatible with existing `config.yml`, `wards.db`, and ward items

---

## 2. Backward Compatibility Guarantees

| Concern | Guarantee |
|---|---|
| `config.yml` | All new keys have defaults; old keys and values unchanged |
| `wards.db` / MySQL | Safe `ALTER TABLE ADD COLUMN ... DEFAULT` migration on startup; existing rows get default values |
| Ward items in player inventories | PDC tag format unchanged; existing items continue to work |
| Existing commands | No command removed or renamed |
| `wards.player.*` permissions | Unchanged |
| Trust level default | All existing members treated as `MEMBER`; zero behaviour change for servers that don't configure trust levels |

## 3. Scope — Four Groups

### G1 · Protection Gaps (8 handlers)

All new and existing protection event handlers moved to `EventPriority.LOWEST` so MachinaWards is always first-responder.

**Replace** existing Bukkit explosion handlers (`EntityExplodeEvent`, `BlockExplodeEvent`) with the cheaper Purpur events that fire *before* block list calculation:

| Old | New Purpur Event |
|---|---|
| `EntityExplodeEvent` | `PreEntityExplodeEvent` |
| `BlockExplodeEvent` | `PreBlockExplodeEvent` |

**Add** six new handlers (all toggled in `config.yml`, default `true`):

| Config Key | Event | Blocks |
|---|---|---|
| `protection.bucket_pour` | `PlayerBucketEmptyEvent` | Non-member pouring lava/water into ward |
| `protection.entity_place` | `EntityPlaceEvent` | Non-member placing armor stands, boats, minecarts |
| `protection.entity_place` (shared) | `PlayerArmorStandManipulateEvent` | Non-member swapping items on armor stands |
| `protection.vehicle_destroy` | `VehicleDamageEvent` | Non-member damaging vehicles inside ward |
| `protection.vehicle_destroy` (shared) | `VehicleDestroyEvent` | Non-member destroying vehicles inside ward |
| `protection.block_spread` | `BlockSpreadEvent` | Fire/sculk/vine spreading INTO ward from outside |
| `protection.spawner_egg` | `PlayerSetSpawnerTypeWithEggEvent` | Non-member changing spawner type inside ward |

**Overlap buffer:** `WardManager.overlaps()` adds `+1` to the total radius sum, creating a 1-block gap between any two wards.

**Trust-aware protection split:**  
`blocked(Player, Block)` → two methods:
- `blockedForBuild(Player, Ward)` — returns `true` if VISITOR or non-member (blocks place/break/bucket/entity place)
- `blockedForInteract(Player, Ward)` — returns `true` only for non-members (VISITOR can interact)

### G2 · Architecture Fixes

**Static maps → instance fields** (`WardMenuListener`):  
`pendingAdd`, `pendingRename`, `pendingMessage` become `private final Map<UUID, UUID>` instance fields (were `static`). Fixes map accumulation across plugin reloads.

**Particle task config caching** (`WardParticleTask`):  
Add `private boolean enabled` and `private Particle particleType` fields, populated in a `reload()` method called from `MachinaWards.onEnable()` and the `reload` command handler.

**MySQL — HikariCP pooling** (`MysqlStore`):  
Replace single `Connection` field with `HikariDataSource`. `plugin.yml` `libraries:` gains `com.zaxxer:HikariCP:5.1.0` (Paper auto-downloads from Maven Central). Add `libs/hikaricp-5.1.0.jar` for compile classpath. `run.sh` adds `HIKARI_JAR` variable and includes it in `CP`. All SQL in `AbstractStore` uses `try (Connection conn = ds.getConnection())`.

**`lastAlert` map pruning** (`WardManager`):  
In `setLastAlert()`, after inserting, if the per-ward entry map size exceeds 200, remove all entries older than `2 × cooldown_ms`. Prevents unbounded memory growth on busy servers.

**Non-blocking offline player lookup** (`WardCommand`):  
Replace `Bukkit.getOfflinePlayer(String)` with `Bukkit.getOfflinePlayerIfCached(String)`. If `null`, reject with `"Player not found (must have joined this server)."` This prevents blocking UUID web lookups on the main thread.

### G3 · Adventure API Migration

All message-sending migrated to `net.kyori.adventure` APIs (available via `libs/adventure-*.jar` and server jar in compile classpath).

**`Msg.java` — new bridge method:**
```java
// Existing c(String) stays for any remaining legacy String use
static Component component(String s) {
    return LegacyComponentSerializer.legacyAmpersand().deserialize(c(s));
}
```
Supports all existing `&X` codes and `&#RRGGBB` hex — no config format change.

**Migration table:**

| Old | New |
|---|---|
| `p.spigot().sendMessage(ChatMessageType.ACTION_BAR, new TextComponent(s))` | `p.sendActionBar(Msg.component(s))` |
| `p.sendTitle(t, st, 5, 30, 10)` | `p.showTitle(Title.title(Msg.component(t), Msg.component(st), Times.times(Ticks.duration(5), Ticks.duration(30), Ticks.duration(10))))` |
| `p.sendMessage(Msg.c(s))` | `p.sendMessage(Msg.component(s))` |
| `AsyncPlayerChatEvent` | `io.papermc.paper.event.player.AsyncChatEvent` |
| `e.getMessage()` (String) | `PlainTextComponentSerializer.plainText().serialize(e.message())` |
| `Bukkit.createInventory(h, n, String)` | `Bukkit.createInventory(h, n, Msg.component(s))` |

Files touched: `EntryListener`, `WardBlocksListener`, `WardMenuListener`, `SuperWardMenuListener`, `WardCommand`, `ShopMenuListener`, `Msg`.

### G4 · Trust Levels

#### Data Model

**New file `TrustLevel.java`:**
```java
public enum TrustLevel {
    VISITOR("Visitor", Material.GRAY_CONCRETE,
        "Can open doors, chests, and containers.",
        "Cannot place or break blocks."),
    MEMBER("Member", Material.GREEN_CONCRETE,
        "Can build, break, and use everything.",
        "Full access like the ward owner.");
    ...
}
```

**`Ward.java` additions:**
```java
private final Map<UUID, TrustLevel> memberTrust = new ConcurrentHashMap<>();

public TrustLevel getMemberTrust(UUID uuid) {
    if (uuid.equals(owner)) return TrustLevel.MEMBER;
    return memberTrust.getOrDefault(uuid, TrustLevel.MEMBER); // default = MEMBER (backward compat)
}
public void setMemberTrust(UUID uuid, TrustLevel level) {
    memberTrust.put(uuid, level);
}
```

`members` `Set<UUID>` is **unchanged** — it remains the "any access" gate. All existing code checking `w.members().contains(uid)` is unaffected.

#### Database

Migration (runs in existing `runMigrations()`, safe to re-run):
```sql
ALTER TABLE members ADD COLUMN trust_level TEXT DEFAULT 'member'
```

`DataStore` interface gains:
```java
void setTrustLevel(UUID wardId, UUID member, String level);
Map<UUID, Map<UUID, String>> loadAllMemberTrusts(); // bulk load on startup
```

`WardManager` gains:
```java
public void setTrustLevel(UUID wardId, UUID memberId, TrustLevel level)
```

#### Config

```yaml
trust_levels:
  enabled: true   # if false, all members behave as MEMBER (full backward compat)

members:
  notify_on_add: true  # notify player when added/removed as ward member
```

#### Protection Logic

`blockedForBuild(Player p, Ward w)`:
1. If `!w.members().contains(pid)` → blocked (non-member)
2. If `!config.getBoolean("trust_levels.enabled", true)` → not blocked (feature off)
3. If `w.getMemberTrust(pid) == TrustLevel.VISITOR` → blocked (visitor can't build)

`blockedForInteract(Player p, Ward w)`:
1. If `!w.members().contains(pid)` → blocked (non-member)
2. Otherwise → not blocked (VISITOR allowed to interact)

#### Member Management GUI

**Main ward menu** — "Members" button opens the new **54-slot Member Management Screen**.

**Member Management Screen (54-slot):**
```
[border][border][WARD INFO  ][border][ADD+ ][border][border][border][border]
[border][HEAD  ][HEAD       ][HEAD  ][HEAD ][HEAD  ][HEAD  ][HEAD  ][border]
[border][HEAD  ][HEAD       ][HEAD  ][HEAD ][HEAD  ][HEAD  ][HEAD  ][border]
[border][HEAD  ][HEAD       ][HEAD  ][HEAD ][HEAD  ][HEAD  ][HEAD  ][border]
[border][HEAD  ][HEAD       ][HEAD  ][HEAD ][HEAD  ][HEAD  ][HEAD  ][border]
[← PREV][border][border     ][BACK  ][border][border][border][border][NEXT→]
```

- **Green-named head** = MEMBER, **Yellow-named head** = VISITOR
- Head lore shows role, can/cannot bullet list, "Click to manage"
- Pagination: 32 heads per page; prev/next arrows shown only when needed
- **BACK** → returns to main ward menu

Clicking any head opens a **27-slot per-member sub-menu**:
```
[border][border][PLAYER HEAD][border][border]
[border][VISITOR            ][border][MEMBER ][border]
[border][border][REMOVE     ][border][BACK ← ]
```

- **VISITOR** (slot 10, gray concrete): lore shows "Can: interact, open chests" / "Cannot: build, break, use buckets"
- **MEMBER** (slot 12, green concrete): lore shows full access description
- **REMOVE** (slot 13, barrier): `Shift+Click` to confirm, no extra dialog
- **BACK** (slot 14, arrow): returns to member list

Active trust level button is enchantment-glowing; inactive is dull. Title: `"Managing: <PlayerName>"`.

#### Member Notifications

When a player is added/removed as a member:
- If online → immediate `sendMessage(Component)` in action bar + chat
- If offline → stored in a transient queue (or checked on `PlayerJoinEvent`)

Message format:
- Added: `"[Ward: <name>] <owner> added you as a <MEMBER/VISITOR>."` 
- Removed: `"[Ward: <name>] You were removed as a member by <owner>."`

## 7. v2.1 Deferred Features

These are confirmed as valuable but intentionally out of scope for v2.0:

- **Ward expiry** — async daily scan; auto-succession (promote most-active member instead of deleting); configurable per-rank thresholds (30 days default, 60 days for VIPs via `wards.player.*` permission meta)
- **Ward upgrade in-place** — AABB overlap check for expanded radius; "Upgrade" button in main menu showing cost diff
- **Transfer confirmation** — 60-second handshake; clickable `[ACCEPT]`/`[DECLINE]` Component chat message; block if recipient at limit
- **PlaceholderAPI** — `%wards_current_name%`, `%wards_current_owner%`, `%wards_current_role%`, `%wards_count%`, `%wards_max%`
- **`/ward who`** — shows owner of ward at your location
- **Ward list pagination** — `/ward list [page]`
- **`/ward admin cleanup <days>`** — preview + confirm bulk-delete inactive wards
